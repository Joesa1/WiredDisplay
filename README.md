# Thunder Display

通过一根雷雳 3 或更新的数据线，将一台 Mac 的桌面扩展或镜像到另一台 Mac。

同一个应用同时包含两种角色：主机负责创建或采集桌面并编码发送；显示器负责接收、解码和全屏显示。应用不需要账号或订阅。

## 下载

当前版本：[Thunder Display 0.6.5](https://github.com/Joesa1/WiredDisplay/releases/tag/v0.6.5)。

请在**两台 Mac 同时安装 0.6.5**。本版本使用通信协议 2，不能与协议 1 的旧版互连。

当前源码为 **0.7.3 开发版（协议 5，尚未发布）**。自行构建时，两端必须一起升级，不能连接协议 4 或更早版本。

| 传输模式 | 用途与边界 |
| --- | --- |
| 低延迟 SDR | 原有 8-bit HEVC/H.264，有损，优先响应速度 |
| 色彩保真 | 10-bit HEVC，按接收屏幕支持选择 sRGB/Display P3，优先渐变；仍是有损 4:2:0，不支持时报错 |
| 无损 RGB | 采集后的 8-bit BGRA 像素原样传输，无视频压缩；带宽高，实际帧率受链路限制，不能消除面板色差或 8-bit 采集量化 |

| Demo 1 · 无损区域 | 实验：两帧在途、LZ4 压缩、变化区域更新；原生 BGRA 像素保持不变 |
| Demo 2 · 无损整帧 | 实验：相同两帧预算与 LZ4 压缩，始终发送整帧，供与 Demo 1 对比 |
| Demo 3 · 系统变化区域 | 实验：一帧在途、ScreenCaptureKit 提供变化区域并以 LZ4 无损传输；无有效区域时发送完整关键帧 |

主机设备页分别选择传输模式和分辨率；每个设备独立保存。面板原生 / 4K 兼容均沿用设备尺寸计算。已知内建面板从随包目录读取真实物理尺寸，外接屏和未知机型使用运行时读数，不再将所有 Retina 面板固定成 4.5K。五个模式都是 SDR，不包含手机校色或 ICC 安装。

| Mac 芯片 | 下载包 |
| --- | --- |
| Apple 芯片（M1、M2、M3 等） | `ThunderDisplay-arm64.zip` |
| Intel 芯片 | `ThunderDisplay-x86_64.zip` |

解压后将 `Thunder Display.app` 放入 `/Applications`，替换旧版并确认打开的是新版本。发送端和显示器端使用同一个应用，只需按各自 Mac 的芯片选择安装包。

## 使用条件

- 主机：macOS 14 或更新版本。
- 显示器：macOS 12.3 或更新版本。
- 两台 Mac 之间使用雷雳数据线；仅充电 USB-C 线不可用。
- 两台 Mac 均已在“系统设置 > 网络”启用“雷雳网桥”。
- 主机实际推送画面时需要允许“屏幕录制”。
- 较新的 macOS 可能要求允许 Thunder Display 使用“本地网络”。

## 网络设置

建议为两端雷雳网桥设置固定 IPv4 地址。固定地址的价值是连接稳定、设备记录不失效；它本身不会降低视频延迟。

| 设置 | MacBook 主机 | iMac 显示器 |
| --- | --- | --- |
| IPv4 | 手动 | 手动 |
| IP 地址 | `10.10.10.2` | `10.10.10.3` |
| 子网掩码 | `255.255.255.0` | `255.255.255.0` |
| 路由器 / DNS | 留空 | 留空 |

避免选用与 VPN 或其他局域网相同的网段。自动分配的 `169.254.x.x` 地址仍可使用，但尚未完成完整双机验证。

## 第一次连接

1. 在准备作为显示器的 iMac 上打开应用，选择“显示器”，点击“作为显示器连接”。
2. 页面会显示该 Mac 的雷雳网桥地址与六位配对码。
3. 在主机 Mac 上点击“添加设备”，录入对端地址和六位配对码。设备名称会在首次握手后自动读取。
4. 可在“配置检查”运行检测。检测会验证雷雳网桥路径、TCP、配对码和接收端屏幕参数，不会启动屏幕录制或创建虚拟显示器。
5. 检测通过后，选择“扩展”或“镜像”，点击“连接”。首次推送时按系统提示允许屏幕录制。
6. 使用扩展模式时，在主机的“系统设置 > 显示器 > 排列”中放置虚拟显示器。

首次配对成功后，两端都会保存对方的设备身份、地址和反向连接凭据。只要未在侧栏“忘记此设备”，下次连接无需再次输入配对码。每台 Mac 的本机配对码稳定保存，不会因断开或重新监听而变化。

## 分辨率建议

| 显示器 | 推荐逻辑桌面 | 实际视频流 |
| --- | --- | --- |
| M1 24 英寸 iMac | `2240 × 1260` | `4480 × 2520` Retina |
| 2017 27 英寸 5K iMac | `2560 × 1440` | `5120 × 2880` Retina |
| 2017 21.5 英寸 4K iMac | `2048 × 1152` | `4096 × 2304` Retina |
| 非 Retina 27 英寸 QHD iMac | `2560 × 1440` | `2560 × 1440` |

M1 iMac 选择“原生清晰”时使用 Retina 后备分辨率，文字更锐利。兼容档会降低编码压力，但文字清晰度也会下降。

## 已实现功能

- 扩展桌面：主机创建并采集虚拟显示器。
- 镜像：主机直接采集主屏幕。
- 硬件 HEVC / H.264 编解码、TCP_NODELAY、有限帧队列和即时呈现。
- 开发版的系统光标随画面采集和传输，不使用独立光标通道。
- PCM 音频中继；采样率由系统采集输出决定，接收端使用有上限的播放队列，链路短暂拥塞时优先避免拖慢视频。
- 实时显示编码吞吐、确认帧率、画面确认往返时间、编码格式和 60 秒传输曲线。
- 配置检查读取实际雷雳网桥，并尽力解析系统报告中的对端连接状态与速率；系统未提供统一字段时会显示未知。
- 空设备列表仍保留“本机状态”入口，可从配置检查或偏好设置返回主工作台。
- 可在偏好设置中切换两套运行中 Dock 图标。

macOS 没有提供通用公开接口来识别每根雷雳线是否为主动线、被动线或其营销代际。应用只报告系统实际给出的链路状态和速率，不猜测线材型号。

## 连接问题

| 现象 | 检查方向 |
| --- | --- |
| 未发现雷雳网桥 | 检查线材、端口、雷雳网桥是否启用以及两端 IPv4 设置。 |
| `localNetworkDenied` | 在“系统设置 > 隐私与安全性 > 本地网络”允许 Thunder Display。 |
| TCP 等待或超时 | 确认显示器端正在监听，地址在同一子网，且本地网络权限已允许。 |
| 配对或协议被拒绝 | 使用显示器当前显示的六码；确认两端都安装 0.6.5。 |
| 检测通过但无法开始画面 | 检查主机“屏幕录制”权限、虚拟显示器创建和硬件编码器。 |
| 字体模糊或比例异常 | 选择与 iMac 对应的分辨率，并在主机“显示器 > 排列”中确认虚拟显示器模式。 |

“应用能打开”或“防火墙已允许”不等于 macOS 已允许本地网络连接。应用内诊断记录会分别显示路径选择、TCP 建立、配对和屏幕参数交换状态。

## 构建

```sh
./build.sh

xcrun swiftc -swift-version 5 Sources/Cable.swift Sources/Wire.swift \
  Tests/TransportCheck.swift -o /private/tmp/thunder-transport-check \
  -framework Network -framework SystemConfiguration
/private/tmp/thunder-transport-check
```

构建产物和 SHA-256 校验文件位于 `dist/`。默认使用临时目录进行 ad-hoc 签名；如需使用 Apple 签名证书，可设置 `WIRED_SIGN_IDENTITY`。

## 手机 Touch Bar（开发分支）

工具区的 **Touch Bar** 可将同一局域网内的手机浏览器变为横屏触控面板，无需安装手机 App，也无需 Mac 配备实体 Touch Bar。打开此功能后，在手机扫码访问显示的地址，再输入 Mac 上的配对码。

- 应用坞：读取常见安装目录中的应用、图标和运行状态，点击启动或激活。
- 音乐：选择 Music 或 Spotify，读取播放信息并控制播放；需要对应播放器运行和 macOS 自动化授权。
- Agent：读取 [Agent Status](https://github.com/therswamhtet/agent-status-pock) 的本地桥接服务。该依赖需单独按其说明设置；本应用不会自动修改 Agent hooks，也无需通过 Pock 渲染手机界面。
- 天气：配置城市和坐标后使用 Open-Meteo。第一版不接 Apple WeatherKit；后者需要 Apple Developer 配置，不能直接读取天气 App 的内部数据。
- 系统控制：按设备能力提供音量、静音、内建屏幕亮度及需辅助功能权限的快捷操作；不支持的控制明确禁用。

每个组件可以在 Mac 端独立启用。应用不提供完整 Pock 插件运行环境，不保证枚举未挂载磁盘中的应用，也不保证外接显示器亮度控制。

HTTP 版本用于可信局域网，配对不提供传输加密；不要将端口转发到公网。访问重置会撤销已配对手机。手机浏览器后台运行及自动常亮受系统限制，旧手机可手动调整自动锁屏设置。实现边界与验证记录见 [Touch Bar 文档](docs/architecture/touch-bar.md)。
