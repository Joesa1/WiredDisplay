## Findings

### P3 · non-blocking · `end` 的常规发送路径尚未实现

- 文档：`docs/architecture/protocol.md:32,58`。
- 代码：`Sources/App.swift:1008,1041-1042,1199-1205,1308-1324`。
- 结论：两端都能处理入站 `end`，接收端也会在握手拒绝时发送它；但正常手动断开通过 `CablePeer.stop()` 关闭 TCP，主机没有发送 `end`。文档的“双向”和“socket close”足以表达互操作边界，后续若将 `end` 作为优雅断开的必经路径，应先补齐实现与测试。

### P3 · non-blocking · 刷新不直接重启 Bonjour 浏览

- 文档：`docs/ui/README.md:92`。
- 代码：`Sources/App.swift:94-102,563-566`、`Sources/Cable.swift:303-321`。
- 结论：Bonjour 浏览在应用启动时持续运行；`refresh` 动作刷新系统雷雳报告并调用 `tick()`，不显式重启 discovery。文案中的“刷新……发现”可以理解为读取当前发现状态，但若需要精确描述，应改为“刷新本机雷雳状态；发现结果由持续浏览更新”。
