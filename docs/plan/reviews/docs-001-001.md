# docs-001 独立审阅

审阅范围：`docs-001` 引入的文档系统，以及其引用的当前 `README.md`、`Sources/`、`Tests/` 和 `build.sh`。

## Findings

### P1 · blocking · 帧长度合同与实现相反

- 设计文档位置：`docs/architecture/protocol.md:14-19`、`docs/architecture/transport.md:34-38`。
- 代码位置：`Sources/Wire.swift:21-26`、`Sources/Wire.swift:38-41`、`Sources/Cable.swift:206-212`。
- 问题：文档称四字节长度“不包含 `PacketKind`”，且引用不存在的 `Wire.maxPayload`。实现写入的是 `payload.count + 1`，读取的长度也包含首个 kind 字节，限制常量名为 `Wire.maximumPacket`。按文档实现新 peer 会发生帧边界错位，无法互连。
- 要求：把协议图和传输层表格改为“length = kind(1) + payload”，使用 `Wire.maximumPacket`，并写明控制消息的 `Wire.decode` 另有 `256 KiB` 限制。

### P1 · blocking · 消息方向与字段合同不对应 Wire v2

- 设计文档位置：`docs/architecture/protocol.md:30-47`、`docs/plan/analysis/current-state.md:28`。
- 代码位置：`Sources/Wire.swift:50-156`、`Sources/App.swift:1019-1042`、`Sources/App.swift:1253-1266`、`Sources/Video.swift:465-500`。
- 问题：文档把 `statistics` 写成显示器到主机、把 `cursor` 写成双向；当前实现由主机 `ScreenSender` 发送 `statistics` 和 `cursor`，显示器消费它们，确认帧才是显示器到主机。`PeerIdentity` 没有应用版本字段，`Hello` 的实际字段名是 `code`，`DisplayProfile` 没有独立 `scale` 或模式列表，`PointerUpdate` 没有按钮或滚动字段。该文档会使后续交互、诊断和 Wire 兼容实现按错误方向接线。
- 要求：按 `Sources/Wire.swift` 的真实 Codable 字段、每个 `PacketKind` 的实际方向和 payload 更新表格；将设备版本归属到 `Hello.appVersion` / `DisplayProfile.appVersion`。

### P1 · blocking · 延迟策略文档错误描述 FrameBudget

- 设计文档位置：`docs/architecture/protocol.md:47`、`docs/architecture/media.md:44-48`。
- 代码位置：`Sources/Wire.swift:159-175`、`Sources/Video.swift:407-420`。
- 问题：文档说队列满时“丢弃旧帧”。实现保留未确认帧，`FrameBudget.reserve` 在达到上限时返回 `nil`，`ScreenSender` 跳过当前新采集帧；源码注释还明确禁止为网络压力丢弃已编码的参考帧。这个差异直接影响低延迟优化和测试预期。
- 要求：把合同改为“最多保留三个未确认帧；达到上限时跳过新的采集帧，收到确认后释放不晚于该序号的预算”，并将 `VideoSurface` 的最新帧覆盖策略与发送端帧预算区分描述。

### P1 · blocking · 界面文档把未实现的设备状态和删除路径写成现有行为

- 设计文档位置：`docs/ui/README.md:60`、`docs/ui/README.md:75-81`、`docs/ui/README.md:119`。
- 代码位置：`Resources/mvp-ui-prototype.html:552-560`、`Resources/mvp-ui-prototype.html:721-726`、`Sources/App.swift:523-596`。
- 问题：文档称失联设备应禁用、忘记设备会清理原生配对凭据。页面只在另一设备为 `connectedId` 时禁用条目；`away` 条目仍可点击。忘记设备只删除 `localStorage` 中的设备，未向原生发送动作；原生也没有 `forget` 分支，所以 `UserDefaults` 内的 `pairingCode.<address>` 未被清理。这不是已实现能力，且尚未在“当前实现偏差”或 backlog 中明确登记。
- 要求：在本次文档基线中标明这两项为待实现差距，并加入有完成定义的 backlog；或先实现原生忘记操作和失联设备状态机，再保留现有合同措辞。

### P1 · blocking · 文档入口包含无法随仓库解析的链接

- 设计文档位置：`docs/INDEX.md:18`。
- 代码位置：仓库边界为 `WiredDisplay/`；目标并非本仓库受版本控制文件。
- 问题：`../../docs/sessions/wired-display.md` 仅在主工作区的特定目录层级可能存在；在本审阅 worktree 和独立 GitHub clone 中均无法解析。`INDEX.md` 是本项目文档入口，不能依赖仓库外的相对路径。
- 要求：移除该 Markdown 链接，改为纯文本说明外部工作区资料；或把需要维护的会话基线纳入本仓库并从 `docs/INDEX.md` 用仓库内相对路径链接。

### P2 · blocking · 验证声明没有可复现的对应检查

- 设计文档位置：`README.md:91-97`、`docs/operations/validation.md:5-13`。
- 代码位置：`Tests/` 仅包含 `TransportCheck.swift` 和已过期的 `ReceiverCheck.py`；`build.sh:1-29` 也不解析 HTML 或验证空设备导航。
- 问题：README 将“原型页面的脚本解析、空设备状态导航和版本资源”列为已校验，但当前仓库没有对应脚本、测试命令或可定位的历史证据；验证文档也只将 HTML/bridge 列为“代码审阅”。这使“已验证”与可重复的验证入口不一致。
- 要求：添加最小可运行的静态 HTML/bridge 验证并在验证文档列出命令，或把 README 改为可溯源的人工审阅记录，不能继续把它列为自动/已校验结论。
